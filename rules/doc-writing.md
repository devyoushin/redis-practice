# 문서 작성 규칙

모든 Redis 지식 문서는 아래 형식과 규칙을 따릅니다.

---

## 필수 섹션 구조

모든 문서는 다음 5개 섹션을 반드시 포함해야 합니다:

```markdown
# {문서 제목}

{한 문장 개요 — 무엇에 관한 문서인지}

---

## 1. 개요
## 2. 설명
### 2.1 핵심 개념
### 2.2 실무 적용 코드
### 2.3 Best Practice
---
## 3. 트러블슈팅
### 3.1 {증상 제목}
#### 증상
#### 원인
#### 해결 방법
---
## 4. 모니터링 및 확인
---
## 5. TIP
```

---

## 언어 규칙

### 한국어 기술 문서
- 본문은 한국어로 작성
- 기술 용어는 영어 원문 병기: `메모리(Memory)`, `클러스터(Cluster)`
- 명령어, 코드, 설정값은 영어 그대로 유지

### 문체
- 명사형 종결체 사용: `~합니다` → `~함`, `사용합니다` → `사용`
- 단, 설명/가이드 문장은 `~합니다` 허용

### 테이블 형식
```markdown
| 컬럼1 | 컬럼2 | 컬럼3 |
|-------|-------|-------|
| 값1   | 값2   | 값3   |
```

## 코드 블록 규칙

### redis-cli 명령어
```redis-cli
# 설명
COMMAND arg1 arg2
```

### redis.conf 설정
```
maxmemory 4gb                    # 최대 메모리 4GB
maxmemory-policy allkeys-lru     # LRU Eviction 정책
```

### Helm values
```yaml
# Bitnami Redis Helm values
master:
  persistence:
    enabled: true
    size: 10Gi
```

### Bash 명령어
```bash
kubectl exec -it redis-master-0 -n redis -- redis-cli -a $REDIS_PASSWORD
```

## 섹션별 필수 내용

### 섹션 2.1 핵심 개념
- 개념 설명 표 (항목/설명/권장값 등)
- 흐름도 또는 ASCII 다이어그램 (복잡한 구조일 경우)

### 섹션 2.2 실무 적용 코드
- 즉시 복붙 가능한 redis-cli 명령어 또는 설정
- 플레이스홀더는 `<REDIS_PASSWORD>`, `<HOST>` 형식으로 명확히 표시

### 섹션 3. 트러블슈팅
- 최소 2개 이상의 실제 발생 가능한 이슈
- 증상 → 원인 → 해결 방법 순서 유지
- 해결 방법에는 즉시 실행 가능한 명령어 포함

### 섹션 4. 모니터링 및 확인
- `redis-cli INFO` 관련 진단 명령어 또는
- Prometheus 지표 테이블 필수 포함

---

## 금지 사항

- 섹션 누락 금지
- 미검증 설정값 기재 금지
- 플레이스홀더 없이 실제 비밀번호/키 기재 금지
- 막연한 조언("잘 설정하세요") 대신 구체적 수치 제시
